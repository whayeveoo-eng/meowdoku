## v0.3.2 — 2026-06-03（美术改版：对齐参考图）

按玩家提供的参考图（`IMG_0668.PNG`）整体调整美术风格与配色，**按钮数量与功能不变**。

### 改动

- **圆角瓷砖棋盘**：每格画成一块圆角瓷砖、瓷砖间留缝露出奶油底色；去掉格线 / 区域边界 / 外框，区域完全靠底色区分。新增 `render/shape.js`（`tileRect` / `roundRectPath`），`grid.js`、`cells.js`、`effects.js` 统一走它。
- **糖果配色**：`REGION_COLORS` 换成更鲜亮饱和的 10 色（珊瑚 / 蜜桃 / 芥末金 / 奶黄 / 嫩绿 / 薄荷 / 天蓝 / 薰衣草 / 樱粉 / 焦糖）。底色改暖奶油 `#f6f0e8`。
- **奶牛猫（tuxedo）**：`drawCat` 重画为黑白奶牛猫——深色身体/耳 + 白脸/白胸 + 白脸上的深色眼 + 粉鼻 + 粉内耳，呼应参考图的猫图标；深色主体不随区域色变，任意瓷砖上都清楚。
- **柔和药丸控件**：HUD、尺寸选择、工具按钮统一为白色圆角药丸 + 轻投影、无硬边框；选中 / 激活态珊瑚填充白字。规则改为参考图同款 **3 个淡紫灰药丸**（一种颜色一只猫 / 同行同列各一只 / 猫咪不能相邻），操作 + 血量提示移到下方小字一行。
- 放对脉冲、放错闪红都改成圆角瓷砖形状 + 珊瑚 / 红配色。

### 测试结论

- 浏览器实测 5×5 / 8×8 / 10×10：瓷砖、缝隙、糖果色、奶牛猫（大小格都清楚）、规则药丸、珊瑚激活态、自动 ✕、放错闪红均正确；控制台零报错。
- 5 个工具按钮（自动叉/撤销/清空/提示/新关）与全部功能保持不变。

## v0.3.0 — 2026-06-03（血量 + 校验放子 + 无需猜关卡）

把游戏从“自由摆放 + 标红冲突”升级为“严格推理 + 血量”玩法（用户反馈）。

### 新增

- **血量（每关 3 ❤️）**：`LIVES = 3`。放错猫扣 1 滴，归零 → 失败弹层（可“再试一次（同一关，同 seed）”或“换一关”）。HUD 用 ❤️/🤍 显示。
- **校验放子**（修复“随便放都成功”）：放猫前校验是否为唯一解的正确格。
  - 正确 → 落子（爪印脉冲 + 自动排除其行/列/九宫格）。
  - 错误 → 扣 1 ❤️、**不落子**、红 ✗ 闪烁、吉祥物提示剩余血量。错误尝试不进撤销栈、血量不可撤回。
  - 已被自动排除（必非猫）的格**不允许尝试放猫**，点它只在 空↔✕ 间切换，避免误扣血。
- **无需猜关卡**（呼应“一步步严格推导过关”）：新增人类式逻辑求解器 `logicalSolve`（规则 R1 区域/R2 行/R3 列唯一候选 + R4 限定法），生成时**只接受能被纯逻辑完全解出的关卡**。这样唯一解之外还保证“不靠猜”，HP 惩罚才公平。

### 实现要点

- `solver.logicalSolve(region, N)`：可靠推导规则迭代到不动点；全解 → 返回猫格，停滞 → null（需要猜，拒绝该关）。
- `generator.generateLevel(..., {requireLogical:true})`：合法布局 → 区域生长 → 精修唯一 → `logicalSolve` 过滤；保留“唯一但需猜”候选做极端兜底。
- `game`：新增 `hp/maxHp/solutionSet`、`attemptCat()` 校验、`gameLost` 事件、`wrongPlacement` 事件、`status:'lost'`。
- `render/effects`：新增 `flashWrong()` 红格闪烁；`render/ui`：HP 红心 HUD + 失败弹层；`index.html`：失败弹层 + 规则补充。

### 测试结论

- `smoke.mjs` 每尺寸 30 关、共 180 关全过，新增**“纯逻辑可解”**校验；零 fallback。生成耗时：5–7 `<4ms`，8 `~6ms`，9 `~19ms`，10 `~109ms`（max 偶发 ~840ms，一次性）。
- 浏览器实测：正确落子 / 错误扣血不落子 / 已排除格不扣血 / 3 次错误失败弹层 / 同 seed 重来恢复 3 ❤️ / 通关弹层，全部正确；控制台零报错。

### 关键决策

- **校验“对照唯一解”而非“仅查冲突”**：因为关卡有唯一解，放在非解格即便暂不与现有猫冲突也是错的；这才符合“从初始盘面严格推导”。校验后冲突永不发生，旧的实时标红退化为安全网。
- **无需猜是 HP 公平的前提**：若关卡需要猜，HP 惩罚就不公平；故加逻辑求解器过滤，保证每关可纯推理通关。生成更慢但体验正确。
- **错误尝试不落子、不可撤回**：避免“试错放猫→撤销→不扣血”刷关；血量是真实代价。
- **已排除格保护**：自动 ✕ 来自正确的猫（必非猫），点它不该扣血，只在 空↔✕ 切换。

## v0.2.1 — 2026-06-03（视觉简化 + 自动排除）

两处体验优化（用户反馈）：

- **统一细格线**：去掉区域之间的深色粗边和粗外框，所有相邻格都用同样的细线；颜色区域只靠**底色**区分，不再刻意画边界。`grid.js` 简化，`THEME.regionBorder` 改为细外框色。
- **自动排除（auto-X）**：放下一只**无冲突**的小猫后，自动给它的整行、整列、九宫格（含斜角）打 ✕——这些格按规则必然不能再放猫。
  - 只信任“无冲突”的猫：若某猫陷入冲突（红），它不再参与推导；冲突解除后自动 ✕ 立即恢复。
  - 自动 ✕ 是**派生**的（`recompute()` 每次从当前猫位重算），移走猫则其自动 ✕ 自动消失（除非被另一只猫覆盖）。
  - 交互优化：点击一个“已被自动 ✕ 的空格”直接放猫（跳过多余的手动 ✕ 一步）；普通空格仍是 空→✕→🐱→空。
  - 新增开关 `FEATURE_FLAGS.autoEliminate`、`board.eliminatedCells()`、`state.autoMarks`、测试钩子 `__meowdoku.autoMarks()`。

测试：浏览器实测自动 ✕ 覆盖行/列/九宫格正确、冲突时消失/解除后恢复、点击跳叉正确；`smoke.mjs` 120 关仍全过；控制台零报错。

## v0.2.0 — 2026-06-03（玩法重定义：猫版 Queens）

把玩法从「数独」改为用户定义的规则集——猫版 LinkedIn「Queens」。这是一次核心重写，不是增量。

### 玩法（用户定义的 9 条规则）

N×N 棋盘（N ∈ 5..10）分成 N 个连通同色区域；每行 / 每列 / 每种颜色恰好 1 只猫，任意两只猫不能挨着（含斜角）；初始无猫，关卡有唯一解。

### 重写

- **core/board**：邻接（国王步）、按区域分组、冲突检测（同行/列/色/相邻）、胜负、区域连通性校验。
- **core/solver**：按区域回溯求解；`countSolutions` 唯一性；`findAltSolution` 找替代解供精修。
- **core/generator**：合法布局 → 多源随机区域生长 → **唯一性精修**（反复破坏替代解，目标解恒定合法）。
- **core/game**：三态循环（空→✕→🐱→空）、撤销、清空、提示、冲突重算、胜负。
- **render/grid**：区域上色 + 细格线 + 区域间粗边 + 外框。
- **render/cells**：程序化小猫剪影、✕ 标记、冲突红底/红猫、选中描边。
- **render/effects**：随 N 适配的脉冲与通关爪雨。
- **render/ui + index.html**：尺寸选择(5×5~10×10) 取代难度/数字盘；工具改为撤销/清空/提示/新关；HUD 改为猫数/用时/冲突。
- **tools/smoke.mjs**：改测区域合法、唯一解、规则、求解一致、零兜底。

### 测试结论

- 生成器 240 关（5..10 各 40）全过：区域合法、唯一解、规则成立、求解一致、零 fallback。
- 生成耗时：5–9 均 `<5ms`，10×10 均值 `~29ms`、max `~110ms`。
- 浏览器实测：三态循环、四类冲突标红、撤销/清空/提示、通关弹层、尺寸切换均正确，控制台零报错。

### 关键决策

- **纯随机区域划分 + 拒绝 行不通**：N=10 跑 4800 次仍无唯一解（~1s）。改为**唯一性精修**——找到任一替代解就把它的某个错误格划给邻区破坏它，目标猫永不移动故目标解恒合法，收敛快且稳（N=10 均值 ~29ms）。这是本版最重要的技术点。
- **N 从 5 起**：N<5 无满足「相邻行列差≥2」的合法布局，恰好对应规则下限。
- **小猫用深炭剪影、不随区域色变**：猫坐在彩色格上，同色会消失；深色在任意柔和底色上都清楚。
- **三态点击**（空→✕→🐱→空）：LinkedIn Queens 的标准操作，单手可玩，✕ 供推理备忘。
